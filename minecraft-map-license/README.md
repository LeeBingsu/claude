# Map License (마인크래프트 1.21.11 Fabric 모드)

특정 월드를 **1회용 활성화 코드**로 잠그고, 코드를 입력한 **플레이어 계정 UUID**에
영구히 묶어 두는 모드입니다. 서버가 필요 없습니다 — 검증에 필요한 것이 전부 jar 안에
들어 있습니다.

> 사용 설명은 두 가지가 있습니다.
>
> - [USAGE.md](USAGE.md) — 한국어·영어, 플레이어용과 제작자용을 모두 포함한 저장소 문서
> - [dist/READ-ME-FIRST.txt](dist/READ-ME-FIRST.txt) — **구매자에게 배포할 영어 안내문.**
>   맵·모드와 함께 압축 파일에 그대로 넣으면 됩니다.

```
맵 구매 → 코드 발급 → 모드 설치 + 월드 진입 → 코드 입력 → 해당 계정으로 영구 해금
```

## 먼저 알아야 할 것 (중요)

서버가 없기 때문에 **"코드 1회 사용"은 그 PC 안에서만 강제됩니다.** 활성화 기록은
`config/map-license/activations.json`에 남는데, 다른 PC에 새로 설치하면 그 파일이
없으므로 같은 코드가 다시 먹힙니다. 즉 **코드를 유출하면 여러 명이 쓸 수 있습니다.**
이건 코드로 막을 수 있는 문제가 아니라 오프라인 방식의 구조적 한계입니다.

그럼에도 이 모드가 막아 주는 것:

- ✅ **"레딧에서 ZIP 받아서 바로 플레이"** — 맵과 모드 파일만으로는 못 들어갑니다.
- ✅ **jar를 뜯어서 코드 알아내기 / 키젠 만들기** — jar에는 코드의 **해시만** 들어 있고
  코드를 만들어 낼 비밀키가 없습니다. 코드는 80비트 랜덤이라 해시에서 역산도 불가능합니다.
- ✅ **한 사람이 산 코드를 친구들에게 뿌리기** — 같은 PC 안에서는 1회로 끝납니다.
- ❌ **모드 jar를 직접 뜯어고치는 사람** — 검사 코드를 지우면 그만입니다. 이건 클라이언트에서
  돌아가는 모든 DRM의 공통 한계입니다. 아래 "모드를 지우면 어떻게 되나" 절을 꼭 읽으세요.
- ❌ **코드 유출 시 회수** — 서버가 없어서 취소(revoke)를 전파할 방법이 없습니다.

유출 회수·계정 진위 확인·PC 간 1회성 강제까지 필요하면 라이선스 서버가 있어야 합니다.
그 경우의 설계는 이 저장소의 대화 기록을 참고하세요 (Mojang `hasJoined` 계정 검증 +
Ed25519 서명 라이선스).

## 맵 제작자 설정 순서

### 1. 맵 월드를 지정한다

완성된 맵 월드를 열고 (OP 권한으로):

```
/maplicense fingerprint
```

`levelName="..."`, `seed=...`가 출력됩니다. 이 값을
`src/main/resources/map-license/gate.json`에 넣습니다.

```json
{
	"mapId": "my-story-map",
	"title": "내 스토리 맵",
	"markerFile": "map-license.json",
	"worldNames": ["my story map"],
	"seeds": [-4172144997902289642],
	"lockTimeoutSeconds": 300
}
```

세 가지 신호(월드 이름 / 시드 / 마커 파일) 중 **하나라도 맞으면** 잠금이 걸립니다.
일부러 겹쳐 놓은 겁니다 — 마커 파일은 지우면 그만이고 폴더 이름은 바꾸면 그만이지만,
시드는 `level.dat` 안에 있고 바꾸면 아직 생성되지 않은 지형이 어긋납니다. 잠금을
벗기려는 사람이 하나만 찾아서는 안 되게 만드는 것이 목적입니다.

`markerFile`을 쓰려면 월드 폴더 최상단에 `map-license.json`을 넣으세요:

```json
{ "mapId": "my-story-map" }
```

`gate.json`은 **jar 안에** 들어갑니다. config 폴더에 두지 않는 이유는 간단합니다 —
플레이어가 수정할 수 있는 파일은 플레이어가 비울 수도 있고, 그러면 클래스 파일을 한 줄도
안 건드리고 잠금이 풀립니다.

### 2. 판매할 코드를 만든다

```bash
python3 tools/generate_codes.py --count 200 \
    --out-codes tools/codes-batch1.txt \
    --out-hashes src/main/resources/map-license/codes.json
```

- `tools/codes-batch1.txt` — **구매자에게 나눠 줄 코드 원본.** 이 코드가 존재하는 유일한
  장소입니다. 잃어버리면 복구할 방법이 없으니 반드시 백업하고, 절대 배포하지 마세요.
  (`.gitignore`에 등록되어 있습니다.)
- `codes.json` — jar에 들어갈 **해시만** 담긴 파일.

같은 `codes.json`에 대고 다시 실행하면 기존 salt를 유지하고 해시를 **추가**합니다.
2차 판매분을 찍어도 1차 코드가 죽지 않습니다.

#### GitHub Actions로 발급하기

로컬 대신 워크플로우에서 찍을 수도 있습니다. Actions 탭 → **Issue map-license activation
codes** → Run workflow (발급 수 / 배치 이름 / 아티팩트 보존일 입력).

한 번의 실행이 이걸 전부 합니다:

1. 코드를 찍어서 `codes.json`에 해시를 추가하고
2. `mod_version`의 마이너 버전을 올리고 (`1.0.0` → `1.1.0` → `1.2.0`)
3. 둘을 함께 브랜치에 커밋·푸시하고
4. **새 해시가 들어간 jar를 같은 실행에서 빌드**하고
5. 코드 배치와 jar를 각각 아티팩트로 올립니다.

4번이 중요합니다. `GITHUB_TOKEN`으로 푸시한 커밋은 다른 워크플로우를 트리거하지 않기
때문에, 여기서 빌드하지 않으면 `build-mod.yml`이 이 커밋을 그냥 지나칩니다.

2번은 jar를 구분하기 위한 것입니다. 결과물 이름이 `mod_version`을 따라가므로, 버전을
올리지 않으면 서로 다른 해시 목록을 담은 jar 두 개가 같은 파일명으로 디스크에 남아
어느 쪽이 최신인지 알 수 없게 됩니다. 배포할 때는 **버전 번호가 가장 높은 jar**를
올리면 되고, 그 jar는 지금까지 발급한 모든 배치의 코드를 전부 인식합니다.

로컬에서 빌드할 때는 `build/libs/`에 옛 버전 jar가 함께 쌓이므로
`./gradlew clean build`로 지우고 만드는 편이 헷갈리지 않습니다.

평문 코드는 `RUNNER_TEMP`에만 쓰고 체크아웃 안에는 절대 두지 않으므로, 실수로 커밋될
경로가 없습니다. 저장소 시크릿 `CODE_BATCH_PASSPHRASE`를 설정해 두면 배치가 AES256으로
암호화되어 올라갑니다 (`gpg --decrypt`로 풀면 됩니다). 설정하지 않으면 평문으로 올라가고
경고가 남습니다.

**아티팩트는 만료됩니다.** 보존일이 지나면 그 배치의 코드는 영영 복구할 수 없습니다
(해시에서 역산이 안 되니까요). 받는 즉시 영구 보관 위치로 옮기세요.

`activations.json`이 다른 빌드의 기록과 섞이지 않도록,
`LicenseStore.INTEGRITY_KEY` 문자열도 배포 전에 아무 값으로나 바꿔 두세요.

### 3. 빌드

```bash
./gradlew build
```

`build/libs/`에 jar가 나옵니다. 옛 버전이 함께 쌓여 있을 수 있으니 **버전 번호가 가장
높은 것**을 배포하세요. 그 jar가 지금까지 발급한 모든 배치의 코드를 인식합니다.

### 4. 구매자에게 보낼 압축 파일

```
[맵이름].zip
├── READ-ME-FIRST.txt        <- dist/READ-ME-FIRST.txt 를 채워서 넣기
├── map-license-1.2.0.jar    <- 버전이 가장 높은 것
└── [맵 월드 폴더]/
```

`READ-ME-FIRST.txt`에는 채워 넣을 자리가 네 군데 있습니다. 코드가 구매자마다 다르므로
판매 건별로 복사해서 채우게 됩니다.

| 자리 | 넣을 내용 |
| --- | --- |
| `[MAP NAME]` | 맵 이름 |
| `[YOUR CODE HERE]` | **구매자마다 다른** 코드 (배치 파일에서 한 줄) |
| `[SUPPORT CONTACT]` | 문의받을 이메일이나 디스코드 |
| `[YOUR NAME HERE]` | 제작자 이름 |

보내기 전에 빈 자리가 남아 있지 않은지 확인하세요:

```bash
grep -n "\[[A-Z ]*\]" READ-ME-FIRST.txt
```

## 플레이어 경험

1. 모드를 넣고 맵 월드에 들어갑니다.
2. 활성화 화면이 뜹니다. ESC로 닫을 수 없고, 화면이 떠 있는 동안 플레이어는 제자리에
   고정되며 블록 설치/파괴/공격/아이템 사용이 전부 막힙니다. (그 상태로 몹에게 맞아
   죽지 않도록 피해도 함께 막습니다.)
3. 코드를 입력하면 그 계정으로 영구 해금됩니다. 다음부터는 화면이 뜨지 않습니다.
4. 5분(`lockTimeoutSeconds`) 안에 입력하지 않으면 연결이 끊깁니다.

코드 입력은 대소문자·하이픈·공백을 가리지 않고, `I`/`l`은 `1`로 `O`는 `0`으로 알아서
읽습니다 (Crockford base32). 영수증 보고 손으로 치다 헷갈릴 일이 없게 한 겁니다.

화면 대신 명령어로도 됩니다:

| 명령어 | 권한 | 설명 |
| --- | --- | --- |
| `/maplicense activate <코드>` | 누구나 | 코드 입력 |
| `/maplicense status` | 누구나 | 내 활성화 상태 확인 |
| `/maplicense fingerprint` | OP 2 | 현재 월드의 이름/시드 출력 |
| `/maplicense revoke <플레이어>` | OP 3 | 계정 연결 해제 (코드는 사용 완료 상태 유지) |

`revoke`는 계정을 잘못 물린 경우를 위한 겁니다. 코드 자체는 계속 "사용됨"으로 남아서,
해제해 준 코드가 두 번 통하는 일은 없습니다.

## 모드를 지우면 어떻게 되나

**그냥 모드를 빼면 잠금 자체가 실행되지 않습니다.** 당연한 이야기지만 중요합니다 —
이 모드만으로는 "모드 없이 맵만 열기"를 막을 수 없습니다.

그래서 모드가 **맵에 필요한 존재**가 되도록 훅을 하나 제공합니다. 활성화 상태가
스코어보드에 반영됩니다:

```mcfunction
execute if score @s maplicense matches 1 run function mymap:chapter1/start
```

맵의 진행(문 열림, 챕터 시작, 스토리 트리거 등)을 이 점수에 걸어 두세요. 모드 없이 월드를
열면 `maplicense` 목표 자체가 없으므로 점수가 잡히지 않고, 스토리가 진행되지 않습니다.
검사를 지우는 것보다 맵 전체의 커맨드 체인을 되살리는 쪽이 훨씬 귀찮은 일이 됩니다.

더 확실하게 하려면 스토리 데이터(대사, 구조물, 스크립트)를 암호화해서 배포하고 모드가
복호화하게 만들어야 합니다. 그건 이 모드의 범위 밖이고, 필요하면 별도로 붙이면 됩니다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `MapLicense` | 진입점. 접속 처리, 코드 검증 흐름 |
| `GateConfig` / `WorldGate` | 어떤 월드를 잠글지 판별 (이름 / 시드 / 마커) |
| `LicenseCodes` | jar에 박힌 해시 목록, 코드 정규화 및 대조 |
| `LicenseStore` | `activations.json` 읽기/쓰기, 행 단위 HMAC 무결성 |
| `LockManager` | 미인증 플레이어 고정, 재프롬프트, 타임아웃 |
| `PlayerRestrictions` | 잠긴 동안 상호작용·피해 차단 |
| `LicenseFlag` | 스코어보드 `maplicense` 반영 |
| `client/ActivationScreen` | 코드 입력 화면 |
| `tools/generate_codes.py` | 코드 발급기 (Java 검증 로직과 해시 동일) |

`activations.json`의 각 행에는 HMAC이 붙습니다. 메모장으로 UUID를 고쳐 넣으면 그 행은
버려집니다. 다만 **디컴파일러까지 막지는 못합니다** — 서버가 없는 설계에서는 플레이어의
PC가 갖고 있지 않은 비밀이 존재할 수 없기 때문입니다. 여기서 유일한 방어선은 jar
자체입니다.

## 요구 사항

- Minecraft 1.21.11 / Fabric Loader 0.16 이상 / Fabric API / Java 21
