# 사진 소설 (Photo Novel)

사진 여러 장이나 zip 을 올리면, **Gemini** 가 장면과 장면 사이에 들어갈 소설 본문을 써 주는
정적 웹페이지입니다. 빌드 도구도, 서버도, 계정도 필요 없습니다.

```
연작:  [도입부] → 사진 1 → [본문] → 사진 2 → [본문] → 사진 3 → [마무리]
단편:  사진 1 → [단편 1]     사진 2 → [단편 2]     사진 3 → [단편 3]
```

## 실행

```bash
# 방법 1: 그냥 열기
xdg-open photo-novel/index.html          # macOS 는 open

# 방법 2: 로컬 서버 (권장 - file:// 에서는 모듈/CORS 제약이 있을 수 있음)
cd photo-novel && python3 -m http.server 8000
# http://localhost:8000
```

## 두 가지 쓰임 (위쪽 탭)

| 탭 | 하는 일 |
| --- | --- |
| **연작 소설** | 사진들을 순서대로 놓고 **사진과 사진 사이**를 이어 한 편으로 만듭니다 |
| **한 장씩 단편** | 사진 **한 장마다 따로** 짧은 단편을 씁니다. 서로 이어지지 않습니다 |

API 키·모델·temperature 같은 **모델 설정은 두 탭이 함께** 쓰고,
**맞춤 지시사항은 탭마다 따로** 있습니다. 마지막으로 보던 탭을 기억합니다.

## 쓰는 순서

1. **API 키** 를 넣습니다. [aistudio.google.com/apikey](https://aistudio.google.com/apikey) 에서 무료로 발급됩니다.
   "이 브라우저에 저장" 을 켜면 localStorage 에만 남습니다.
2. **목록 불러오기** 를 눌러 계정에서 쓸 수 있는 모델 중 하나를 고릅니다.
   목록에 없는 모델은 "모델 이름 직접 입력" 으로 적어도 됩니다.
3. **맞춤 지시사항** 에 문체·시점·인물 설정·금지사항 등을 자유롭게 적습니다. 매 요청에 그대로 전달됩니다.
4. **사진** 을 끌어다 놓습니다. zip, 이미지 여러 장, 폴더 모두 됩니다.
5. **생성 시작**.

## 순서 규칙

`1.jpg, 2.jpg, 10.jpg` 처럼 **사람이 기대하는 이름 순서**로 정렬합니다
(`10` 이 `2` 앞에 오는 일이 없습니다). zip 안의 폴더 경로도 폴더 단위로 비교하고,
한글 이름과 `IMG_0007.JPG` 같은 접두사 이름도 숫자 부분을 기준으로 맞춥니다.
정렬이 마음에 들지 않으면 목록에서 드래그하거나 ▲▼ 로 직접 바꿀 수 있고,
**이름순 재정렬** 로 언제든 되돌릴 수 있습니다.

사진 목록은 **누르면 접었다 펼 수 있습니다**. 9장 이상이 되는 순간 한 번 자동으로 접어
아래 내용을 볼 때 매번 스크롤하지 않게 합니다. 접고 편 상태는 그대로 기억합니다.

## 어떻게 쓰는가

한 번에 전부 던지지 않고, **사진 사이 구간마다 한 번씩** 따로 요청합니다.

- **1번 사진 앞**에도 도입부를 한 대목 씁니다(끌 수 있습니다). 1번 사진만 보고, 그 순간에 도착하면서 끝나는 글입니다.
- *i* 번째 요청에는 **직전 사진 + 다음 사진 + 지금까지의 줄거리 + 바로 앞까지 쓴 본문**이 함께 들어갑니다.
- 모델에게는 "앞 장면이 끝난 직후부터 시작해, **다음 사진이 보여주는 순간에 정확히 도착하면서** 끝내라"
  고 지시합니다. 그래서 다음 사진이 갑자기 튀어나오지 않습니다.
- 사진을 설명하는 말투("사진 속에는…"), 제목, 장면 번호는 금지되어 있습니다.
- 사진이 많아 앞 내용이 길어지면 뒤쪽 일부만 잘라 보냅니다(길이 조절 가능).

## 장기 일관성 메모

사진이 열 장, 스무 장으로 늘어나면 앞 내용을 다 보낼 수 없어 인물 이름이나 계절이 흔들리고,
앞에서 이미 한 일을 또 합니다. 그래서 두 가지를 따로 쌓아 두고 매 요청에 함께 보냅니다.

**줄거리** — 구간마다 무슨 일이 있었는지 한 줄씩.

```
1번 장면 앞 · 도입부: 해원이 새벽에 집을 나섰다.
1→2번 장면 사이: 버스를 타고 바다로 향했다.
2→3번 장면 사이: 방파제에서 지오를 만났다.
```

**설정** — 인물(이름·호칭·외모·말투), 관계, 장소, 시간대, 소품, 문체. 새로 생기거나 달라진 것만 덧붙입니다.

한 대목을 쓸 때마다 메모 전체를 다시 쓰게 하지 않고 **그 구간의 줄거리 한 줄과 달라진 설정만** 받습니다.
쌓는 일은 앱이 하므로, 사진이 몇 장이든 매 요청에 더 드는 출력은 한두 줄뿐입니다.

메모를 얻는 방법은 두 가지입니다.

| 방식 | 추가 요청 | 비고 |
| --- | --- | --- |
| **같은 요청에 함께** (기본) | **없음** | 본문 뒤에 `<<<메모>>>` 표시줄과 노트를 같이 받아 화면에서는 떼어 냅니다 |
| 따로 요청 | 대목마다 1회 | 본문과 완전히 분리되므로 표시줄이 본문에 샐 여지가 없습니다 |

줄거리 한 줄은 늘 받고, **설정**은 갱신 주기(대목마다 / 2·3·5대목마다)에만 묻습니다.
마지막 대목에서는 어느 쪽도 만들지 않습니다 — 그 뒤에 쓸 곳이 없기 때문입니다.

표시줄이 오지 않으면 그 응답은 전부 본문으로 보고 이전 메모를 그대로 씁니다. 스트리밍 중 표시줄이
반쯤 도착한 상태도 화면에 새지 않습니다.

둘 다 결과 카드의 **이야기 메모** 상자에서 직접 보고 고칠 수 있습니다. 틀린 설정을 고쳐 두면
다음 대목부터 바로 반영되고, 추가 요청도 들지 않습니다.
(줄거리를 고칠 때는 `1→2번 장면 사이:` 같은 앞머리를 지켜 주세요.)

## 한 장씩 단편

사진 한 장을 주고 그 사진만의 짧은 단편을 받습니다. 사진마다 요청 한 번입니다.

- 이 탭에는 **단편 전용 맞춤 지시사항**이 따로 있습니다. 연작용 지시사항과 섞이지 않습니다.
  **분량·형식·문체·시점을 모두 여기서 정합니다** — "300자 안팎, 두 문단", "제목 한 줄과 본문",
  "제목 없이 세 문장만" 처럼 적으면 그대로 따릅니다.
- 고르는 것은 **쓸 언어(원문)** 하나뿐입니다. 연작 쪽의 대목 분량·시점·도입부 같은 설정은
  사진마다 따로 쓰는 이 탭과 상관이 없어 끌어오지 않습니다.
  API 키·모델·temperature·재시도 같은 모델 설정만 위 설정을 함께 씁니다.
- 제목을 붙이면(첫 줄 `제목: …`) 카드와 그림에 제목으로 들어가고, 없으면 본문만 씁니다.
  제목과 본문 모두 직접 고칠 수 있습니다.
- 막히면 연작과 같은 규칙으로 다시 시도합니다(거부·빈 응답일 때 설정을 따릅니다).

### 번역

카드마다 **한국어 / English / 日本語** 단추가 있습니다. 아직 없는 언어를 누르면 그때 한 번 옮기고,
한 번 옮긴 뒤로는 눌러서 오가는 데 요청이 들지 않습니다. 원문에는 `(원문)` 이 붙습니다.
옮긴 글도 직접 고칠 수 있고, 그림으로 저장할 때는 **지금 보고 있는 언어**가 들어갑니다.

번역은 **무료 번역 API** 로 합니다. 모델에게 시키면 내용에 따라 "정책상 거부" 가 나지만,
번역기는 글을 검열하지 않고 들어온 문장을 그대로 옮깁니다. **API 키가 필요 없습니다.**

| 번역 방식 | 키 | 비고 |
| --- | --- | --- |
| **자동** (기본) | 없음 | LibreTranslate 로 해 보고, 막히면 MyMemory 로 한 번 더 |
| LibreTranslate | 없음 | 서버 주소를 바꿀 수 있습니다. 직접 띄운 서버도 됩니다 |
| MyMemory | 없음 | 이메일을 적어 두면 하루 한도가 늘어납니다 |
| 고른 Gemini 모델 | 필요 | 문체는 가장 잘 살지만 거부당할 수 있습니다 |

- 긴 글은 줄과 문장 단위로 나눠 보내고, 원문의 줄 모양 그대로 다시 붙입니다(빈 줄은 보내지 않습니다).
- 한 번 옮긴 글은 저장되므로 같은 언어를 다시 눌러도 요청이 들지 않습니다.
- 공개 서버가 느리거나 막히면 방식을 바꾸거나 LibreTranslate 서버 주소를 직접 넣으세요.

### 그림으로 저장

**올린 사진 원본 위에** 글을 얹어 한 장의 그림으로 만듭니다.

- 사진을 어둡게(0~90%), 글자 크기, 글 위치(위/가운데/아래), 정렬, 제목 표시, 파일 형식(JPEG/PNG)을 고릅니다.
  제목이 없는 글이면 본문만 얹힙니다.
- 글이 놓이는 쪽에는 옅은 그라데이션을 한 겹 더 깔고 글자에 그림자를 넣어, 밝은 사진에서도 읽힙니다.
- 줄바꿈은 한글·가나는 글자 단위로, 라틴 낱말은 낱말 단위로 끊습니다.
- **크기는 원본 그대로입니다.** 모델에 보낼 때만 사진을 줄이고(이미지 최대 변 길이),
  그림으로 저장할 때는 줄이기 전 원본에 글을 얹습니다.
- 카드마다 저장하거나, **전체 그림으로 저장 (.zip)** 으로 한 번에 받습니다. `.txt` 로 글만 받을 수도 있습니다.

단편도 자동 저장과 **전체 내보내기(.zip)** 에 함께 담깁니다(단편 사진은 원본으로 담기고,
불러올 때 지금 설정에 맞춰 보낼 크기를 다시 만듭니다).

## 검열(안전 필터)

`safetySettings` 를 **가장 느슨한 단계부터** 보냅니다.

| 단계 | 내용 |
| --- | --- |
| 1 | 5개 카테고리 전부 `OFF` (필터 자체를 끔) |
| 2 | `OFF`, 시민 무결성 카테고리 제외 |
| 3 | 5개 카테고리 전부 `BLOCK_NONE` |
| 4 | `BLOCK_NONE`, 시민 무결성 제외 |
| 5 | 모델 기본값 |

`OFF` 를 받아주지 않는 모델이면 오류 메시지를 보고 **자동으로 한 단계씩 내려가며 다시 시도**하고,
그 결과를 기억해 이후 요청에 그대로 씁니다. 고급 옵션에서 시작 단계를 직접 고를 수도 있습니다.
다만 API 쪽 정책 차단(`PROHIBITED_CONTENT`)은 클라이언트에서 끌 수 있는 값이 아닙니다.
그래서 그런 응답이 오면 **같은 자리에서 다시 씁니다**(아래).

## 막혔을 때 다시 쓰기

"모델이 정책상 생성을 거부했습니다", 안전 필터, 빈 응답으로 끝난 대목은 그냥 넘어가면
이야기 중간에 구멍이 남습니다. 고급 옵션의 **거부·빈 응답일 때** 에서 정합니다.

| 값 | 동작 |
| --- | --- |
| 그냥 넘어가기 | 그 대목만 실패로 표시하고 다음 대목으로 (예전 방식) |
| **3·5·10번까지** (기본 3) | 그만큼 다시 써 보고, 그래도 안 되면 넘어간다 |
| 될 때까지 | **그 대목이 나오기 전에는 다음으로 넘어가지 않는다.** 성공하거나 **중단**을 누를 때까지 |

- 다시 보낼 때 "앞선 시도가 끊겼다, 다른 문장으로 써라" 는 안내를 덧붙입니다.
  temperature 등 설정값은 건드리지 않습니다 — 화면에 적어 둔 값 그대로 갑니다.
- 기다리는 간격은 1초 → 2초 → 4초 …로 늘어나며 최대 15초입니다(요청 간 대기를 설정했다면 더해집니다).
- **여러 번 막히면 더 우회적으로 쓰도록 요청**(기본 꺼짐)을 켜면, 두 번째 재시도부터
  "직접적인 묘사 대신 암시와 여백으로, 내용과 방향은 그대로" 라고 부탁합니다.
- 429(분당 제한)나 서버 오류로 실패한 경우도 같은 규칙으로 다시 걸어 봅니다.
  API 키가 틀렸다거나 권한이 없는 경우처럼 다시 걸어도 소용없는 오류는 바로 멈춥니다.
### 무엇이 막혔는지 알려 줍니다

`PROHIBITED_CONTENT`(금지 콘텐츠 정책)는 **안전 필터 설정으로 끌 수 없는 별도의 층**입니다.
`safetySettings` 를 전부 `OFF` 로 보내도 여기 걸리면 막힙니다. 대신 **어디서** 막혔는지를 구분해 보여 줍니다.

| 표시 | 뜻 | 볼 곳 |
| --- | --- | --- |
| "보낸 내용이 …에 걸렸습니다" | 요청 자체가 거절됨 | 사진, 맞춤 지시사항, 앞 본문·메모 |
| "쓰던 중 …에 걸려 중단됐습니다" | 쓰다가 끊김 | 이야기가 흘러간 방향 |

같은 입력을 다시 보내면 같은 판정이 나오므로, "보낸 내용" 쪽이면 무엇을 뺄지부터 정해야 합니다.
특히 매 요청에 **앞 본문과 줄거리 메모가 함께 실려 가기 때문에**, 앞쪽 어딘가가 걸리면
그 뒤 대목이 줄줄이 같은 이유로 막힙니다.

### 재시도를 다 쓰면 뺄 것을 빼고 한 번 더 (기본 켜짐)

오래 쓰다 보면 **딸려 가는 것들** 중 하나가 걸립니다. 한번 걸리면 매 요청에 그것이 실려 가므로
뒤 대목까지 계속 막힙니다. 그래서 고른 재시도 횟수를 다 쓰고도 막히면, 마지막으로
**고른 항목을 빼고** 한 번 더 보냅니다.

| 뺄 항목 | 기본 | 빼면 |
| --- | --- | --- |
| 설정 메모 | ✅ | 인물·장소 설정이 흔들릴 수 있음 |
| 줄거리 | ✅ | 앞에서 한 일을 또 할 수 있음 |
| 앞뒤 본문 | ✖ | 문장 연결이 거칠어짐 |
| 직전 사진 | ✖ | 장면 전환이 덜 매끄러움 |
| 맞춤 지시사항 | ✖ | 문체가 달라짐 |

기본값(설정 메모 + 줄거리)이면 **사진과 앞뒤 본문은 그대로** 가므로 이야기는 끊기지 않습니다.
아무것도 고르지 않으면 이 추가 시도를 하지 않습니다.
"될 때까지" 를 골랐다면 4번째 시도부터 계속 이 방식으로 보내고,
"그냥 넘어가기" 를 골랐다면 이 한 번도 하지 않습니다.

이렇게 받은 대목에는 "(뺀 항목) 없이 쓴 대목입니다" 라고 표시가 남습니다.
어긋난 곳이 있으면 그 대목만 **다시 쓰기** 하거나, 메모 상자에서 걸리는 줄을 지우면 됩니다.

- 몇 번을 써도 계속 막히면 그 대목에 "n번 시도했지만 계속 막혔습니다" 라고 남기고 다음으로 갑니다.
  나중에 **다시 쓰기** 를 눌러 그 대목만 따로 시도할 수 있습니다.

### 구멍이 생겨도 이야기가 어긋나지 않게

한 대목을 건너뛰면 그 뒤가 없는 셈 치고 이어져 앞뒤가 붕 뜹니다. 그래서 세 가지를 합니다.

- 줄거리 메모에 그 구간을 `(비어 있음 — 아직 쓰지 않은 구간)` 으로 적어 보냅니다.
- 구멍 **바로 다음 대목**에는 "직전 구간이 비어 있으니, 시작할 때 그 사이의 일을
  한두 문장으로 자연스럽게 흘려 넣어라" 고 시킵니다. 읽는 사람 눈에는 끊기지 않습니다.
- 나중에 그 구멍을 **다시 쓰기** 로 채울 때는 **뒤에 이미 쓰인 본문을 함께 보여 주고**
  "그 첫 문장에 자연스럽게 닿도록 끝내고, 거기 있는 내용을 되풀이하지 마라" 고 시킵니다.

구멍을 채운 뒤 그다음 대목이 조금 겹쳐 보이면, 그 대목도 한 번 **다시 쓰기** 하면 깔끔해집니다.

## 그 밖의 옵션

- 대목 분량 / 언어 / 시점 / 시제
- temperature, top_p, 최대 출력 토큰, thinking 예산 (미지원 모델이면 자동으로 빼고 재시도)
- 요청 간 대기 시간 (무료 등급 분당 요청 제한 회피용)
- 이미지 최대 변 길이 — 기본 1568px 로 줄여서 보냅니다. `0` 이면 원본 그대로.
  GIF·BMP 처럼 API 가 받지 않는 형식은 JPEG 로 자동 변환합니다.

## 전체 내보내기 / 불러오기

결과 카드의 **전체 내보내기 (.zip)** 는 작업 전체를 zip 하나로 묶습니다.

```
photo-novel.json     사진 목록·순서, 대목 본문, 줄거리, 설정 메모, 화면 설정
story.txt            사람이 그냥 읽을 수 있는 본문
images/001-1.jpg     사진 원본 바이트 (앱이 들고 있는 그대로)
images/002-2.jpg
```

- 사진은 **바이너리 그대로** 담습니다. HTML 내보내기의 base64 와 달리 크기가 부풀지 않습니다.
- **API 키는 담기지 않습니다.** 파일을 남에게 줘도 키가 새지 않습니다.
- **전체 불러오기** 로 그 zip 을 열면 사진·순서·본문·줄거리·설정 메모·화면 설정이 전부 되살아납니다.
  브라우저를 바꾸거나 다른 기기로 옮길 때, 작업을 여러 개 보관할 때 쓰면 됩니다.
- 불러온 내용은 자동 저장에도 곧바로 반영되므로 새로고침해도 남습니다.
- 사진만 든 평범한 zip 을 넣으면 그렇다고 알려 줍니다(그건 사진 올리기로 넣으면 됩니다).

## 저장되는 것

| 항목 | 어디에 |
| --- | --- |
| 맞춤 지시사항, 모델, 모든 옵션, 테마, 화면 글자 크기 | localStorage |
| API 키 | localStorage — "이 브라우저에 저장" 을 켠 경우에만 |
| **사진(원본 blob), 소설 본문, 사진 순서, 일관성 메모** | IndexedDB — 고급 옵션의 "사진과 본문 자동 저장"(기본 켜짐) |

사진과 본문은 바뀔 때마다 자동으로 저장되고, 다음에 페이지를 열면 그대로 복원됩니다.
며칠 뒤에 들어와서 "빈 대목만 이어서" 로 이어 쓸 수 있습니다.
결과 카드 아래에 마지막 저장 시각이 표시되고, 같은 줄의 **저장된 작업 지우기** 로 비울 수 있습니다.
자동 저장을 끄면 저장해 둔 것도 함께 지워집니다. 저장 공간이 부족해지면 자동 저장을 멈추고 그 사실을 알려 줍니다.
모두 이 브라우저 안에만 남습니다.

- 페이지를 열면 **지난 작업을 다 읽을 때까지 저장하지 않습니다.** 읽는 도중 화면이 꺼지거나 다른 앱으로
  넘어가도 빈 화면이 저장본을 덮어쓰지 않습니다. 읽기에 실패하면 자동 저장을 멈추고 알려 주며,
  **저장된 작업 지우기**를 누르기 전까지는 저장본을 건드리지 않습니다.
- 올린 사진은 **바이트를 복사해서** 담습니다. 폰 갤러리에서 사진을 지워도 저장본과 백업은 그대로입니다.
  (예전 버전은 안드로이드에서 폰 파일을 가리키는 참조를 저장해, 사진을 지우면 저장본을 읽지 못하고 작업 전체가
  열리지 않았습니다. 예전에 저장된 사진은 다음에 열 때 아직 읽히면 복사본으로 다시 저장합니다.)
- 사진 한 장을 못 읽어도 나머지 사진과 글은 모두 되살리고, 못 읽은 자리는 회색 칸으로 지켜 대목이 밀리지 않게 합니다.
- 저장은 **사이트 주소마다 따로**입니다. `http://` 와 `https://`, 개인 도메인과 `github.io` 는 서로 다른 저장소라
  주소가 바뀌면 이전 작업이 보이지 않습니다. 소중한 작업은 **전체 내보내기(.zip)** 로 따로 받아 두세요.

## 만화 (컷마다 말풍선)

세 번째 탭. 사진 한 장이 한 컷입니다. 컷마다 **간단한 시나리오**를 적으면 Gemini 가 사진과 시나리오를 보고
인물들의 대사를 써서 **말풍선으로 사진 위에 얹어** 줍니다. 그 뒤 말풍선의 모양·색·위치·크기·글자체를 마음대로 고칩니다.

**만드는 순서**

1. 컷 사진을 올립니다 (`1.jpg, 2.jpg …` 이름 순서가 컷 순서, zip 도 됩니다).
2. 컷 편집 칸에서 컷마다 시나리오를 적습니다. 비워 두면 사진만 보고 씁니다.
3. 등장인물(이름·말투, 선택)과 만화 전용 맞춤 지시사항, 컷마다 말풍선 최대 개수를 정하고 **말풍선 글 만들기**.
   앞선 컷의 시나리오와 대사를 함께 보내 이름과 말투가 이어집니다(끌 수 있습니다).
4. 대사가 만들어지면 말풍선은 **아직 사진 위에 없는 상태(미배치)** 로 컷 아래 목록에 나옵니다. 앱은 자리를 정하지 않습니다.
   **사진을 터치하면 그 자리가 말풍선의 가운데가 되어 놓이고**, 다음 미배치 말풍선이 차례로 놓을 순서가 됩니다(안내 줄이 무엇을 놓을 차례인지 알려 줍니다).
   터치한 채 **말하는 사람 쪽으로 끌면 꼬리가 그쪽을 가리킵니다.** 그냥 톡 터치하면 꼬리는 아래쪽으로 나옵니다.
   다른 것을 먼저 놓으려면 목록에서 그 말풍선을 고르고, 잘못 놓았으면 **다시 놓기**를 눌러 다시 터치합니다.
   모델에게는 위치를 요구하지 않습니다(글에 맞춘 크기만 자동으로 잡습니다).
   손가락으로 배치하는 동안에는 사진 위에서 화면이 스크롤되지 않으니, 사진 옆 여백을 잡고 스크롤하세요.

**말풍선 고치기** — 사진 위에서 말풍선을 누르면 고칠 수 있습니다.

## 브라우저 사본 (두 번째 저장)

자동 저장(사진과 글을 나눠 담는 IndexedDB)과 **별도로**, 프로젝트 전체를 **zip 하나로 다른 저장소(`photoNovelMirror`)에 한 번 더** 둡니다.
사진 **원본**·글·단편·만화(말풍선·글꼴)·모든 설정이 들어갑니다(API 키는 보안상 제외 — "이 브라우저에 저장"을 켜면 따로 남습니다).
주소가 https 라서 Cache Storage 를 쓸 수 있으면 거기에도 함께 둡니다.

- 작업이 바뀌고 15초 뒤에 자동으로 만들고(쓰는 중이면 끝난 뒤), 탭을 덮을 때도 만듭니다. 설정 → 백업의 **브라우저 저장소에 사본을 하나 더 자동 저장**(기본 켜짐)으로 끕니다.
- **열 때 기본 저장소가 비어 있거나 읽히지 않으면 이 사본에서 자동으로 되살립니다.** 직접 **브라우저 사본에서 되살리기**를 누를 수도 있습니다.
- **저장된 작업 지우기**·자동 저장 끄기·사본 끄기를 하면 사본도 함께 지웁니다(지운 작업이 되살아나지 않도록). 화면에 남은 내용은 **바꾸기 전에는** 탭을 닫아도 다시 저장하지 않습니다.
- 사진이 250MB 를 넘으면 메모리 부담이 커서 만들지 않습니다. 그때는 파일 백업을 쓰세요.
- 저장 공간 사용량과 **브라우저의 삭제 보호(영구 보관)** 상태를 보여 줍니다. 보호 요청은 https(또는 localhost)에서만 가능하고, http 로 열면 저장 공간이 모자랄 때 브라우저가 이 데이터를 먼저 지울 수 있습니다.
- 두 저장소 모두 같은 사이트의 브라우저 데이터라 **"사이트 데이터 삭제"를 하면 함께 사라집니다.** 그런 경우를 위해 아래 파일 백업이 따로 있습니다.
- 연작 사진도 이제 **줄이기 전 원본**을 함께 저장·백업합니다(전에는 모델에 보내는 줄인 사진만 남았습니다). 불러올 때 지금 설정에 맞춰 다시 줄입니다.

## 백업 (파일로)

설정 → **백업 (파일로)**.

- **자동 백업**(기본 켜짐): 연작·단편 쓰기가 끝날 때마다 `photo-novel-backup-날짜-시각.zip` 을 내려받습니다.
  처음 한 번은 브라우저가 "여러 파일 다운로드" 허용을 물을 수 있습니다.
- **지금 백업 받기**: 언제든 직접 받습니다.
- **백업에서 되살리기**: 그 zip 을 고르면 연작 사진·본문·줄거리·설정 메모, 단편 사진 원본·글·번역, 설정까지
  모두 돌아옵니다. 빈 브라우저·다른 폰에서도 됩니다. 되살린 뒤 그림으로 저장·글 추가를 그대로 이어 갈 수 있습니다.

백업 파일은 전체 내보내기와 같은 형식이라 서로 바꿔 쓸 수 있습니다.

### 설정 파일 (.json)

같은 칸의 **설정 파일로 저장** 은 맞춤 지시사항(연작·단편), 모델, 모든 옵션, 번역·AI 티 빼기·그림 설정,
테마와 글자 크기를 JSON 파일 하나로 받습니다. **API 키 포함** 을 켜 두면 키도 들어갑니다(기본 켜짐).
**설정 파일 불러오기** 로 다른 브라우저·폰에서도 그대로 되살립니다. 키가 들어 있으면 "이 브라우저에 저장" 도 켜집니다.
사진과 글은 담기지 않습니다 — 그건 백업 zip 이 맡습니다. 키가 든 파일은 남과 공유하지 마세요.

## 생성 중에 자리를 비울 때

브라우저 페이지는 탭이 닫히면 거기서 멈춥니다. 탭을 닫아 두고 계속 생성하는 것은
정적 웹페이지로는 불가능합니다. 대신 자리를 비웠다 돌아오는 흐름을 이렇게 받칩니다.

- **생성 중 화면 꺼짐 방지**(기본 켜짐) — 휴대폰에서 화면이 꺼지면 페이지가 얼어붙어
  생성이 멈춥니다. 생성하는 동안만 화면 잠금을 잡고, 끝나면 바로 놓습니다.
  탭을 다시 보면 브라우저가 풀어 둔 잠금을 다시 잡습니다.
- **다시 열면 남은 대목 이어 쓰기**(기본 켜짐) — 탭이 닫혔거나 휴대폰이 페이지를
  잠재웠어도, 다시 열면 남은 대목부터 알아서 이어 씁니다.
  API 키를 저장해 둔 경우에만 자동으로 시작하고, 시작 전 1.5초 동안 중단할 틈을 줍니다.
  꺼 두면 "남은 대목이 n개 있습니다" 라고만 알려 줍니다.
- 인터넷이 끊기면 **다시 연결될 때까지 기다렸다가** 이어서 씁니다(재시도 횟수를 축내지 않습니다).
- 쓰다 만 대목은 저장하지 않습니다. 조각난 문장이 완성본으로 남아 이어쓰기가
  건너뛰는 일이 없습니다.

생성 중에 화면이 저절로 움직이지 않습니다. 글이 써지는 동안에도 보던 자리에 그대로 머뭅니다.

## AI 티 빼기 (imnotai.kr)

쓴 글을 [imnotai.kr](https://imnotai.kr/app) 의 한국어 윤문(`POST /api/humanize`)에 넣어 AI 티를 뺍니다.
연작 대목과 단편 모두, **대목/단편마다 단추**로 돌리거나 **쓰자마자 자동으로** 돌릴 수 있습니다.
설정 → **AI 티 빼기** 칸에서 정합니다.

- 윤문 방식은 `fast` / `precision`, "보이지 않는 문자 정리"(sanitize)도 그대로 넘깁니다.
- 한 번에 2만 자까지 받으므로, 더 긴 글은 문단 경계에서 나눠 보냅니다.
- 진행 상황(`윤문하는 중`, `이음매·리듬 점검 중` …)이 상태줄에 그대로 나옵니다.
- **실패해도 원문은 지우지 않습니다.** 그 대목에 실패 사유만 적어 두고 다음으로 갑니다.
- 자동으로 돌리면 뒤 대목이 참고하는 앞 글도 다듬어진 글이 됩니다.

### 프록시가 필요한 이유

imnotai.kr 의 API 는 자기 웹앱에서만 쓰라고 만든 것이라 **CORS 가 열려 있지 않습니다**
(`OPTIONS` 는 204 를 주지만 `Access-Control-Allow-Origin` 이 없습니다).
그래서 브라우저에서 곧장 부르면 응답을 읽지 못하고, **직접 띄운 중계 서버 주소**를 적어야 합니다.
주소를 비워 두면 이 기능은 꺼진 채로 단추도 보이지 않습니다.

적어 준 주소는 이렇게 씁니다.

| 적은 주소 | 실제로 부르는 곳 |
| --- | --- |
| `https://내서버/humanize` | 그대로 (직접 띄운 중계 서버) |
| `https://프록시/?url={url}` | `{url}` 자리에 대상 주소를 넣어서 |
| `https://프록시/?url=` | 끝에 대상 주소를 붙여서 |
| `https://프록시/` | 끝에 대상 주소를 그대로 이어 붙여서 |

Cloudflare Workers 로 띄운다면 이 정도면 됩니다. 아래는 누구나 쓸 수 있게 열어 둔 가장 단순한 모양이고,
`'*'` 대신 사진 소설이 열리는 **실제 주소**만 허용하는 편이 안전합니다. GitHub Pages 에 개인 도메인(`CNAME`)을
붙였다면 `github.io` 가 아니라 그 도메인이 출처가 되고, `http`/`https` 도 따로 셈합니다.
연결 확인에서 "프록시에 닿지 못했습니다" 가 나오면 문구에 적힌 사이트 주소를 허용 목록에 넣으세요.

```js
export default {
  async fetch(req) {
    const cors = {
      'Access-Control-Allow-Origin': '*',
      'Access-Control-Allow-Headers': 'content-type',
      'Access-Control-Allow-Methods': 'POST, OPTIONS'
    };
    if (req.method === 'OPTIONS') return new Response(null, { status: 204, headers: cors });
    const res = await fetch('https://imnotai.kr/api/humanize', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: await req.text()
    });
    return new Response(res.body, { status: res.status, headers: { ...cors, 'content-type': 'application/x-ndjson' } });
  }
};
```

> imnotai.kr 은 남의 서비스이고 시범운영 중입니다. 많은 양을 한꺼번에 돌리지 말고,
> 상대가 막으면 그 뜻을 따르세요. 설정 → AI 티 빼기의 **연결 확인**으로 먼저 한 문장만 시험해 볼 수 있습니다.

## 화면 글자 크기

머리말의 **가 −  /  가 100%  /  가 ＋** 로 읽는 글자 크기를 70%~200% 사이에서 조절합니다.
연작 대목과 단편 본문·제목이 함께 움직이고, 줄 간격과 여백도 배율을 따라갑니다.
가운데 값을 누르면 100% 로 돌아가고, 고른 크기는 다음에 열 때도 남습니다.
브라우저 전체 확대(Ctrl +/−)와 달리 단추나 입력칸은 그대로 두고 본문만 키웁니다.

그림으로 저장할 때 얹히는 글자 크기는 이것과 별개입니다 — 단편 탭 **결과** 칸의
"그림으로 저장할 때 모양 → 글자 크기" 에서 사진 가로폭에 대한 비율로 정합니다.

생성 도중 **중단**할 수 있고, **빈 대목만 이어서** 로 실패한 구간만 다시 채울 수 있습니다.
각 대목은 **다시 쓰기** 로 개별 재생성하거나, 본문을 직접 눌러서 고칠 수 있습니다.
결과는 복사 / `.txt` / `.md` / `.html`(사진까지 포함된 한 파일) / `.zip`(작업 전체) 로 내보냅니다.
