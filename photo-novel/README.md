# 사진 소설 (Photo Novel)

사진 여러 장이나 zip 을 올리면, **Gemini** 가 장면과 장면 사이에 들어갈 소설 본문을 써 주는
정적 웹페이지입니다. 빌드 도구도, 서버도, 계정도 필요 없습니다.

```
[도입부]  →  사진 1  →  [소설 본문]  →  사진 2  →  [소설 본문]  →  사진 3  →  [마무리]
```

## 실행

```bash
# 방법 1: 그냥 열기
xdg-open photo-novel/index.html          # macOS 는 open

# 방법 2: 로컬 서버 (권장 - file:// 에서는 모듈/CORS 제약이 있을 수 있음)
cd photo-novel && python3 -m http.server 8000
# http://localhost:8000
```

## 쓰는 순서

1. **API 키** 를 넣습니다. [aistudio.google.com/apikey](https://aistudio.google.com/apikey) 에서 무료로 발급됩니다.
   "이 브라우저에 저장" 을 켜면 localStorage 에만 남습니다.
2. **목록 불러오기** 를 눌러 계정에서 쓸 수 있는 모델 중 하나를 고릅니다.
   목록에 없는 모델은 "모델 이름 직접 입력" 으로 적어도 됩니다.
3. **맞춤 지시사항** 에 문체·시점·인물 설정·금지사항 등을 자유롭게 적습니다. 매 요청에 그대로 전달됩니다.
4. **사진** 을 끌어다 놓습니다. zip, 이미지 여러 장, 폴더 모두 됩니다.
5. **생성 시작**.

## 순서 규칙

`1.jpg, 2.jpg, 10.jpg` 처럼 **사람이 기대하는 이름 순서**로 정렬합니다
(`10` 이 `2` 앞에 오는 일이 없습니다). zip 안의 폴더 경로도 폴더 단위로 비교하고,
한글 이름과 `IMG_0007.JPG` 같은 접두사 이름도 숫자 부분을 기준으로 맞춥니다.
정렬이 마음에 들지 않으면 목록에서 드래그하거나 ▲▼ 로 직접 바꿀 수 있고,
**이름순 재정렬** 로 언제든 되돌릴 수 있습니다.

사진 목록은 **누르면 접었다 펼 수 있습니다**. 9장 이상이 되는 순간 한 번 자동으로 접어
아래 내용을 볼 때 매번 스크롤하지 않게 합니다. 접고 편 상태는 그대로 기억합니다.

## 어떻게 쓰는가

한 번에 전부 던지지 않고, **사진 사이 구간마다 한 번씩** 따로 요청합니다.

- **1번 사진 앞**에도 도입부를 한 대목 씁니다(끌 수 있습니다). 1번 사진만 보고, 그 순간에 도착하면서 끝나는 글입니다.
- *i* 번째 요청에는 **직전 사진 + 다음 사진 + 지금까지의 줄거리 + 바로 앞까지 쓴 본문**이 함께 들어갑니다.
- 모델에게는 "앞 장면이 끝난 직후부터 시작해, **다음 사진이 보여주는 순간에 정확히 도착하면서** 끝내라"
  고 지시합니다. 그래서 다음 사진이 갑자기 튀어나오지 않습니다.
- 사진을 설명하는 말투("사진 속에는…"), 제목, 장면 번호는 금지되어 있습니다.
- 사진이 많아 앞 내용이 길어지면 뒤쪽 일부만 잘라 보냅니다(길이 조절 가능).

## 장기 일관성 메모

사진이 열 장, 스무 장으로 늘어나면 앞 내용을 다 보낼 수 없어 인물 이름이나 계절이 흔들리고,
앞에서 이미 한 일을 또 합니다. 그래서 두 가지를 따로 쌓아 두고 매 요청에 함께 보냅니다.

**줄거리** — 구간마다 무슨 일이 있었는지 한 줄씩.

```
1번 장면 앞 · 도입부: 해원이 새벽에 집을 나섰다.
1→2번 장면 사이: 버스를 타고 바다로 향했다.
2→3번 장면 사이: 방파제에서 지오를 만났다.
```

**설정** — 인물(이름·호칭·외모·말투), 관계, 장소, 시간대, 소품, 문체. 새로 생기거나 달라진 것만 덧붙입니다.

한 대목을 쓸 때마다 메모 전체를 다시 쓰게 하지 않고 **그 구간의 줄거리 한 줄과 달라진 설정만** 받습니다.
쌓는 일은 앱이 하므로, 사진이 몇 장이든 매 요청에 더 드는 출력은 한두 줄뿐입니다.

메모를 얻는 방법은 두 가지입니다.

| 방식 | 추가 요청 | 비고 |
| --- | --- | --- |
| **같은 요청에 함께** (기본) | **없음** | 본문 뒤에 `<<<메모>>>` 표시줄과 노트를 같이 받아 화면에서는 떼어 냅니다 |
| 따로 요청 | 대목마다 1회 | 본문과 완전히 분리되므로 표시줄이 본문에 샐 여지가 없습니다 |

줄거리 한 줄은 늘 받고, **설정**은 갱신 주기(대목마다 / 2·3·5대목마다)에만 묻습니다.
마지막 대목에서는 어느 쪽도 만들지 않습니다 — 그 뒤에 쓸 곳이 없기 때문입니다.

표시줄이 오지 않으면 그 응답은 전부 본문으로 보고 이전 메모를 그대로 씁니다. 스트리밍 중 표시줄이
반쯤 도착한 상태도 화면에 새지 않습니다.

둘 다 결과 카드의 **이야기 메모** 상자에서 직접 보고 고칠 수 있습니다. 틀린 설정을 고쳐 두면
다음 대목부터 바로 반영되고, 추가 요청도 들지 않습니다.
(줄거리를 고칠 때는 `1→2번 장면 사이:` 같은 앞머리를 지켜 주세요.)

## 검열(안전 필터)

`safetySettings` 를 **가장 느슨한 단계부터** 보냅니다.

| 단계 | 내용 |
| --- | --- |
| 1 | 5개 카테고리 전부 `OFF` (필터 자체를 끔) |
| 2 | `OFF`, 시민 무결성 카테고리 제외 |
| 3 | 5개 카테고리 전부 `BLOCK_NONE` |
| 4 | `BLOCK_NONE`, 시민 무결성 제외 |
| 5 | 모델 기본값 |

`OFF` 를 받아주지 않는 모델이면 오류 메시지를 보고 **자동으로 한 단계씩 내려가며 다시 시도**하고,
그 결과를 기억해 이후 요청에 그대로 씁니다. 고급 옵션에서 시작 단계를 직접 고를 수도 있습니다.
다만 API 쪽 정책 차단(`PROHIBITED_CONTENT`)은 클라이언트에서 끌 수 있는 값이 아닙니다.
그래서 그런 응답이 오면 **같은 자리에서 다시 씁니다**(아래).

## 막혔을 때 다시 쓰기

"모델이 정책상 생성을 거부했습니다", 안전 필터, 빈 응답으로 끝난 대목은 그냥 넘어가면
이야기 중간에 구멍이 남습니다. 고급 옵션의 **거부·빈 응답일 때** 에서 정합니다.

| 값 | 동작 |
| --- | --- |
| 그냥 넘어가기 | 그 대목만 실패로 표시하고 다음 대목으로 (예전 방식) |
| **3·5·10번까지** (기본 3) | 그만큼 다시 써 보고, 그래도 안 되면 넘어간다 |
| 될 때까지 | **그 대목이 나오기 전에는 다음으로 넘어가지 않는다.** 성공하거나 **중단**을 누를 때까지 |

- 다시 보낼 때 "앞선 시도가 끊겼다, 다른 문장으로 써라" 는 안내를 덧붙입니다.
  temperature 등 설정값은 건드리지 않습니다 — 화면에 적어 둔 값 그대로 갑니다.
- 기다리는 간격은 1초 → 2초 → 4초 …로 늘어나며 최대 15초입니다(요청 간 대기를 설정했다면 더해집니다).
- **여러 번 막히면 더 우회적으로 쓰도록 요청**(기본 꺼짐)을 켜면, 두 번째 재시도부터
  "직접적인 묘사 대신 암시와 여백으로, 내용과 방향은 그대로" 라고 부탁합니다.
- 429(분당 제한)나 서버 오류로 실패한 경우도 같은 규칙으로 다시 걸어 봅니다.
  API 키가 틀렸다거나 권한이 없는 경우처럼 다시 걸어도 소용없는 오류는 바로 멈춥니다.
### 무엇이 막혔는지 알려 줍니다

`PROHIBITED_CONTENT`(금지 콘텐츠 정책)는 **안전 필터 설정으로 끌 수 없는 별도의 층**입니다.
`safetySettings` 를 전부 `OFF` 로 보내도 여기 걸리면 막힙니다. 대신 **어디서** 막혔는지를 구분해 보여 줍니다.

| 표시 | 뜻 | 볼 곳 |
| --- | --- | --- |
| "보낸 내용이 …에 걸렸습니다" | 요청 자체가 거절됨 | 사진, 맞춤 지시사항, 앞 본문·메모 |
| "쓰던 중 …에 걸려 중단됐습니다" | 쓰다가 끊김 | 이야기가 흘러간 방향 |

같은 입력을 다시 보내면 같은 판정이 나오므로, "보낸 내용" 쪽이면 무엇을 뺄지부터 정해야 합니다.
특히 매 요청에 **앞 본문과 줄거리 메모가 함께 실려 가기 때문에**, 앞쪽 어딘가가 걸리면
그 뒤 대목이 줄줄이 같은 이유로 막힙니다.

### 재시도를 다 쓰면 뺄 것을 빼고 한 번 더 (기본 켜짐)

오래 쓰다 보면 **딸려 가는 것들** 중 하나가 걸립니다. 한번 걸리면 매 요청에 그것이 실려 가므로
뒤 대목까지 계속 막힙니다. 그래서 고른 재시도 횟수를 다 쓰고도 막히면, 마지막으로
**고른 항목을 빼고** 한 번 더 보냅니다.

| 뺄 항목 | 기본 | 빼면 |
| --- | --- | --- |
| 설정 메모 | ✅ | 인물·장소 설정이 흔들릴 수 있음 |
| 줄거리 | ✅ | 앞에서 한 일을 또 할 수 있음 |
| 앞뒤 본문 | ✖ | 문장 연결이 거칠어짐 |
| 직전 사진 | ✖ | 장면 전환이 덜 매끄러움 |
| 맞춤 지시사항 | ✖ | 문체가 달라짐 |

기본값(설정 메모 + 줄거리)이면 **사진과 앞뒤 본문은 그대로** 가므로 이야기는 끊기지 않습니다.
아무것도 고르지 않으면 이 추가 시도를 하지 않습니다.
"될 때까지" 를 골랐다면 4번째 시도부터 계속 이 방식으로 보내고,
"그냥 넘어가기" 를 골랐다면 이 한 번도 하지 않습니다.

이렇게 받은 대목에는 "(뺀 항목) 없이 쓴 대목입니다" 라고 표시가 남습니다.
어긋난 곳이 있으면 그 대목만 **다시 쓰기** 하거나, 메모 상자에서 걸리는 줄을 지우면 됩니다.

- 몇 번을 써도 계속 막히면 그 대목에 "n번 시도했지만 계속 막혔습니다" 라고 남기고 다음으로 갑니다.
  나중에 **다시 쓰기** 를 눌러 그 대목만 따로 시도할 수 있습니다.

### 구멍이 생겨도 이야기가 어긋나지 않게

한 대목을 건너뛰면 그 뒤가 없는 셈 치고 이어져 앞뒤가 붕 뜹니다. 그래서 세 가지를 합니다.

- 줄거리 메모에 그 구간을 `(비어 있음 — 아직 쓰지 않은 구간)` 으로 적어 보냅니다.
- 구멍 **바로 다음 대목**에는 "직전 구간이 비어 있으니, 시작할 때 그 사이의 일을
  한두 문장으로 자연스럽게 흘려 넣어라" 고 시킵니다. 읽는 사람 눈에는 끊기지 않습니다.
- 나중에 그 구멍을 **다시 쓰기** 로 채울 때는 **뒤에 이미 쓰인 본문을 함께 보여 주고**
  "그 첫 문장에 자연스럽게 닿도록 끝내고, 거기 있는 내용을 되풀이하지 마라" 고 시킵니다.

구멍을 채운 뒤 그다음 대목이 조금 겹쳐 보이면, 그 대목도 한 번 **다시 쓰기** 하면 깔끔해집니다.

## 그 밖의 옵션

- 대목 분량 / 언어 / 시점 / 시제
- temperature, top_p, 최대 출력 토큰, thinking 예산 (미지원 모델이면 자동으로 빼고 재시도)
- 요청 간 대기 시간 (무료 등급 분당 요청 제한 회피용)
- 이미지 최대 변 길이 — 기본 1568px 로 줄여서 보냅니다. `0` 이면 원본 그대로.
  GIF·BMP 처럼 API 가 받지 않는 형식은 JPEG 로 자동 변환합니다.

## 전체 내보내기 / 불러오기

결과 카드의 **전체 내보내기 (.zip)** 는 작업 전체를 zip 하나로 묶습니다.

```
photo-novel.json     사진 목록·순서, 대목 본문, 줄거리, 설정 메모, 화면 설정
story.txt            사람이 그냥 읽을 수 있는 본문
images/001-1.jpg     사진 원본 바이트 (앱이 들고 있는 그대로)
images/002-2.jpg
```

- 사진은 **바이너리 그대로** 담습니다. HTML 내보내기의 base64 와 달리 크기가 부풀지 않습니다.
- **API 키는 담기지 않습니다.** 파일을 남에게 줘도 키가 새지 않습니다.
- **전체 불러오기** 로 그 zip 을 열면 사진·순서·본문·줄거리·설정 메모·화면 설정이 전부 되살아납니다.
  브라우저를 바꾸거나 다른 기기로 옮길 때, 작업을 여러 개 보관할 때 쓰면 됩니다.
- 불러온 내용은 자동 저장에도 곧바로 반영되므로 새로고침해도 남습니다.
- 사진만 든 평범한 zip 을 넣으면 그렇다고 알려 줍니다(그건 사진 올리기로 넣으면 됩니다).

## 저장되는 것

| 항목 | 어디에 |
| --- | --- |
| 맞춤 지시사항, 모델, 모든 옵션, 테마 | localStorage |
| API 키 | localStorage — "이 브라우저에 저장" 을 켠 경우에만 |
| **사진(원본 blob), 소설 본문, 사진 순서, 일관성 메모** | IndexedDB — 고급 옵션의 "사진과 본문 자동 저장"(기본 켜짐) |

사진과 본문은 바뀔 때마다 자동으로 저장되고, 다음에 페이지를 열면 그대로 복원됩니다.
며칠 뒤에 들어와서 "빈 대목만 이어서" 로 이어 쓸 수 있습니다.
결과 카드 아래에 마지막 저장 시각이 표시되고, 같은 줄의 **저장된 작업 지우기** 로 비울 수 있습니다.
자동 저장을 끄면 저장해 둔 것도 함께 지워집니다. 저장 공간이 부족해지면 자동 저장을 멈추고 그 사실을 알려 줍니다.
모두 이 브라우저 안에만 남습니다.

## 생성 중에 자리를 비울 때

브라우저 페이지는 탭이 닫히면 거기서 멈춥니다. 탭을 닫아 두고 계속 생성하는 것은
정적 웹페이지로는 불가능합니다. 대신 자리를 비웠다 돌아오는 흐름을 이렇게 받칩니다.

- **생성 중 화면 꺼짐 방지**(기본 켜짐) — 휴대폰에서 화면이 꺼지면 페이지가 얼어붙어
  생성이 멈춥니다. 생성하는 동안만 화면 잠금을 잡고, 끝나면 바로 놓습니다.
  탭을 다시 보면 브라우저가 풀어 둔 잠금을 다시 잡습니다.
- **다시 열면 남은 대목 이어 쓰기**(기본 켜짐) — 탭이 닫혔거나 휴대폰이 페이지를
  잠재웠어도, 다시 열면 남은 대목부터 알아서 이어 씁니다.
  API 키를 저장해 둔 경우에만 자동으로 시작하고, 시작 전 1.5초 동안 중단할 틈을 줍니다.
  꺼 두면 "남은 대목이 n개 있습니다" 라고만 알려 줍니다.
- 인터넷이 끊기면 **다시 연결될 때까지 기다렸다가** 이어서 씁니다(재시도 횟수를 축내지 않습니다).
- 쓰다 만 대목은 저장하지 않습니다. 조각난 문장이 완성본으로 남아 이어쓰기가
  건너뛰는 일이 없습니다.

생성 중에 화면이 저절로 움직이지 않습니다. 글이 써지는 동안에도 보던 자리에 그대로 머뭅니다.

생성 도중 **중단**할 수 있고, **빈 대목만 이어서** 로 실패한 구간만 다시 채울 수 있습니다.
각 대목은 **다시 쓰기** 로 개별 재생성하거나, 본문을 직접 눌러서 고칠 수 있습니다.
결과는 복사 / `.txt` / `.md` / `.html`(사진까지 포함된 한 파일) / `.zip`(작업 전체) 로 내보냅니다.

## 개인정보

번들도 CDN 도 없고, 외부로 나가는 요청은 `generativelanguage.googleapis.com` 하나뿐입니다.
사진과 API 키는 브라우저를 떠나 다른 서버로 가지 않습니다.

## 구조

```
photo-novel/
├── index.html
├── styles.css
├── app.js              화면 로직
├── lib/
│   ├── zip.js          외부 라이브러리 없는 zip 리더·라이터 (De/CompressionStream)
│   ├── sort.js         사람이 기대하는 이름 순 정렬
│   ├── images.js       파일/zip → 이미지 레코드 (축소·변환 포함)
│   ├── store.js        IndexedDB 자동 저장·복원
│   ├── project.js      전체 내보내기·불러오기(zip) 꾸리기와 검사
│   ├── gemini.js       REST 호출, SSE 스트리밍, 안전 옵션 단계적 완화, 재시도
│   └── prompt.js       시스템 지시문과 구간별 프롬프트
└── test/run-tests.js   node 로 도는 단위 테스트
```

```bash
node photo-novel/test/run-tests.js
```
